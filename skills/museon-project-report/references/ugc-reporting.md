# UGC / Museon reporting

Use this route only after the user selects UGC and a customer from the Museon source. Inspect current CLI schema before calling campaign-monitor commands. The bundled report.py/render_card.py implement HireAICreator schedules; they are not UGC collectors or schedulers.

1. Discover accessible workspaces, paginate campaign-monitor lists within the chosen organization, and show real customer/project names with workspace context. Let the user choose; do not assume the same customer's AI and UGC campaigns share IDs. Save `project_type=ugc`, `source=museon`, workspace and campaign IDs. Distinguish partial sub-campaign coverage from a whole customer.
2. For a management report based on MuseOn Task, use Task as the project roster and verify each binding against Museon. Do not silently create Task bindings from name similarity. For a user's selected customer report, use only that selected scope, not every authorized customer.
3. Query the selected campaign's summary and content list, with complete pagination where required. Use the agreed project start date through the current date. Confirm the live schema, response semantics, timezone, metric coverage and freshness. A narrow yesterday-only publication filter can exclude yesterday's growth on older posts.
4. Default preview: yesterday's new content, yesterday's incremental views, cumulative views, cumulative content and top 3 videos, expandable to 10. Reuse the yellow report header, yellow total and centered bold project names. Show target progress only when targets and scope are verified. Do not invent AI-style promotion/warmup schedules for UGC data that lacks them.

For `campaign-performance-v3` summaries, verified daily trend fields are `period_content_count` and `period_views`; overview uses `total_content` and `total_views`. Check the semantics version before using these fields. `campaign-monitor +list`'s `yesterday_metrics.views` is cumulative views on yesterday-published content, not yesterday's incremental views. Missing values remain unavailable, not zero. If the CLI cannot select a timezone, label its actual UTC day boundary rather than calling it a Beijing calendar day. Content count is not necessarily a video-only count. Filter TOP entries to verified videos and use actual returned platform links/IDs.

Use the project's publication cohort for both totals and TOP. Do not include old-account posts from other customers. Keep AI and UGC totals separate unless the user requests a combined total with an explicit deduplication and coverage rule.

Generate and review the real-data preview, then send/read back through the authorized Feishu profile. Keep snapshots, receipts and any local report implementation outside the public package. This package does not include a UGC scheduling adapter: test and validate a UGC-specific execution path before configuring recurring delivery. Do not run the AI helper or report UGC automation as enabled just because onboarding completed. Daily summaries can use the host's supported scheduler once that UGC path is verified. Post-publication checkpoints require timestamped stored observations; cumulative history cannot recreate missing 30m/2h/6h snapshots.
